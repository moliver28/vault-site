🔍 Common Workflows

Workflow 1: Analyze Single Document

User: "Analyze this council disclosure document"

Agent:
1. OCR (if image/PDF): pytesseract.image_to_string()
2. Extract entities: extract_entities(text)
3. Extract relationships: extract_relationships(text)
4. Detect conflicts: analyze_case_file()
5. Return: "Found X people, Y orgs, Z relationships. Flagged N conflicts: [list]"

Time: <5 seconds
Accuracy: 95%+ on entities

Workflow 2: Start New Investigation

User: "Start investigation into [subject]"

Agent:
1. Create case file (INV-YYYY-NNN)
2. Create Notion page
3. Ask for initial evidence/documents
4. Run document-analysis on provided docs
5. Auto-populate: subjects, timeline, evidence log
6. Return: "Case INV-2026-XXX created. Found X subjects, Y leads."

Time: <10 seconds
Output: Structured case file + Notion page

Workflow 3: Process Evidence Batch

User: "Process these 10 disclosure PDFs for case INV-2026-001"

Agent:
1. For each PDF:
   a. OCR with Tesseract/PaddleOCR
   b. Extract entities with document-analysis
   c. Extract relationships
   d. Log to evidence registry (E001, E002, ...)
   e. Compute SHA256 hash
2. Merge all entities, deduplicate
3. Build unified relationship graph
4. Flag all conflicts
5. Update case file + Notion
6. Return: "Processed 10 docs. Found X unique people, Y orgs, Z conflicts."

Time: ~30 seconds for 10 docs
Accuracy: 95%+ on entities, 100% reproducible

Workflow 4: Generate Handoff Package

User: "Generate handoff package for INV-2026-001"

Agent:
1. Read case file + all evidence
2. Run document-analysis on full corpus
3. Generate 10-section package:
   - Case Summary (2 pages)
   - Evidence Index (Excel)
   - Source Contacts
   - Interactive Timeline (Bokeh)
   - Document Archive (OCR'd PDFs)
   - Legal Memo (risk assessment)
   - Publication Draft
   - Follow-Up Leads
   - Methodology Notes
   - Notion Link
4. Export to ~/investigations/INV-2026-001-Handoff/
5. Return: "Handoff package ready at [path]. Notion link: [URL]"

Time: 2-5 minutes
Output: Publication-ready package

🔧 Troubleshooting

Problem: GLiNER slow on first run

Cause: Downloading model (~100MB)
Fix: Wait for first run, subsequent runs are fast
Alternative: Pre-download model

Problem: Tesseract missing languages

Cause: Only English installed by default
Fix:

Problem: Resource temporarily unavailable

Cause: Race condition during pip install
Fix: Wait 30 seconds, retry
Alternative: Use different terminal session

Problem: Overlapping entities (GLiNER vs spaCy)

Cause: Both models detect same entity differently
Fix: Merge carefully, prefer GLiNER for custom types

🔐 Security & Privacy

  • ✅ All processing is local — No API calls for entity extraction or OCR
  • ✅ No data leaves your machine — GLiNER, spaCy, Tesseract all run locally
  • ✅ Chain of custody — SHA256 hashes for all evidence
  • ✅ Reproducible — Deterministic extraction, same input = same output
  • ⚠️ Notion sync — Case data syncs to Notion (encrypted in transit)

For sensitive cases:

  • Disable Notion sync
  • Use OnionShare for source intake
  • Encrypt case files at rest
  • Use secure deletion for temporary files
