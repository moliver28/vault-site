Vault conventions for investigations

These rules apply to every case, current and future. They exist so a reader can move between cases without relearning the furniture, and so a new case can be scaffolded in one pass.

The folder contract

Investigations/
  Investigations.md              hub, the only entry point
  <YYMM-slug>/                   one folder per case
    <YYMM-slug>.md               case file, machine-read by the pipeline
    <Name> Brief.md              the story, about a thousand words
    <Name> Findings.md           graded claims, each with a source
    <Name> Questions.md          open items and the reply round
    <Name> Timeline.md           generated from the case file
    <Name> Record.md             generated register of record/
    <Name> People.md             generated entity index, when profiles exist
    record/                      raw evidence, verbatim, never rewritten
      rendered/                  verbatim .md views of .txt files
  _system/                       engine, generators, conventions
  _archive/                      tarballs and manifests for retired material
  _templates/                    case brief, finding, record templates

The underscore prefix sorts system folders after the cases and marks them as machinery. record/ sorts after the reading notes inside a case.

The note contract

Every note carries frontmatter: project, type, status, created. Case notes add case. Generated notes add generator, so a reader can tell what will be overwritten.

Types in use: case-brief, case-findings, case-questions, case-timeline, case-record, case-people, case-method, index, convention, review, system-index.

The writing contract

  • The reading layer carries the author’s voice. The record does not. Evidence files stay verbatim, including their errors, because a corrected original is no longer evidence.
  • Write for a reader who has not seen the case. Expand an acronym on first use in each note.
  • One idea per paragraph. Thesis in the first tenth of the note.
  • Link every claim to the graded row that supports it. A claim without a row is an opinion and belongs in a review note.
  • No em dashes. The house style uses commas, colons, or parentheses.

The evidence contract

  • Grades: verified, corroborated, speculative, misleading. Only the first two publish as fact.
  • A verified absence is publishable as an absence, not as conduct.
  • Corrections are additive. Add a banner that points at the correction; do not rewrite the old document, and do not delete it.
  • Every retired file goes to _archive/ as a tarball with a SHA-256 in the manifest. Nothing is deleted.

Progressive disclosure

Non-investigation material sits behind one door each:

  • _system/ is excluded from search and graph and opens through System.
  • _archive/ is excluded and opens through Archive.
  • Inside a note, long file lists sit in collapsed callouts (> [!evidence]-), so the page opens short and the depth is one click away.
  • Bases dashboards always have a plain table fallback, because the public viewer does not render Bases.

Starting a new case

  1. Create the folder as YYMM-slug.
  2. Put the case file at the root with its frontmatter and evidence log.
  3. Mirror raw material into record/, then run render for any .txt files.
  4. Write the brief, findings, and questions. Gate them: voice.py check <file> --min-score 85.
  5. Generate the derived notes:
python3 Investigations/_system/scripts/vault_cases.py record   Investigations/<slug> --name <Name> --write
python3 Investigations/_system/scripts/vault_cases.py timeline Investigations/<slug> --name <Name> --write
python3 Investigations/_system/scripts/vault_cases.py people   Investigations/<slug> --name <Name> --write
python3 Investigations/_system/scripts/vault_cases.py check
  1. Link the case from the hub and add a row to the dashboard.
  2. Run the lint gate before letting the sync tick publish.

Entity links

An entity that recurs across notes gets one canonical note under Investigations/Entities/, with aliases in the frontmatter. The linkifier points the first mention in each note at that note, up to six entities per page.

  • Run linkify.py --apply --ner to discover, create, and link; --dry-run must report zero opportunities afterwards.
  • Never link a place or an institutional common noun. Lakewood, Washington, Council, and County are blocked on purpose.
  • Evidence under record/ is never edited, and links are never inserted into headings, table rows, or code.
  • The state snapshot in _system/data/links.json lists every link the tool owns.
