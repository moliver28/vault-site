What Is an Agentic Workflow? The Definition Cognitive Science Already Had

What Is an Agentic Workflow? The Definition Cognitive Science Already Had

Properties1
tagshuman-ai-collaboration, frameworks--and--models, human-factors

Nov 14, 202611 min read

The AI industry spent two years defining “agentic workflow.” Cognitive scientists defined the same thing four decades ago. The gap between these two definitions is where most agentic systems fail.

The Agentic Workflow Definition Everyone Agrees On

An agentic workflow is a multi-step process where an AI agent breaks down a complex goal, reasons about how to achieve it, takes actions, and refines its approach through iteration.
That much should be familiar. Andrew Ng outlined four design patterns that anchor most implementations [1]: reflection (the agent critiques and improves its own output), tool use (the agent interacts with external systems and data), planning (the agent decomposes a complex task into manageable steps), and multi-agent collaboration (specialized agents coordinate to solve problems no single agent could handle alone).
The industry consensus is clear. IBM defines agentic workflows as “AI-driven processes where autonomous agents make decisions, take actions, and coordinate tasks with minimal human intervention” [2]. AWS, NVIDIA, and Atlassian offer variations on the same theme [3][4][5]. Every major tech company has published its version.
What these definitions share is a focus on what agentic workflows do: they reason, they plan, they act, they adapt. What they miss is why these particular patterns work. And understanding the “why” is how you build systems that don’t break in unpredictable ways.
The answer has been sitting in HCI textbooks since 1983.

What Cognitive Science Already Knew

The four patterns that define modern agentic workflows map directly to cognitive process models that researchers have studied, validated, and refined for decades. This isn’t a loose analogy. The structural parallels are precise enough to be useful.

GOMS: The Original Task Decomposition

In 1983, Stuart Card, Thomas Moran, and Allen Newell published The Psychology of Human-Computer Interaction, introducing the GOMS model: Goals, Operators, Methods, and Selection Rules [6]. GOMS describes how humans decompose complex tasks into hierarchical goal structures, select methods to achieve sub-goals, and execute operators (the atomic actions that actually change the world).
Read that list again: goals, operators, methods, selection rules. Now consider how you design an agentic workflow. You define a goal for the agent. You give it operators (tool calls, API actions, code execution). You specify methods (chains, strategies, prompts that achieve sub-goals). And you build selection rules (routing logic that chooses between methods based on context).
GOMS is the cognitive blueprint that agentic workflow architects have been unknowingly replicating. The model predicted, 40 years in advance, that any system performing complex tasks would need exactly these four components. Not because they are elegant engineering choices, but because they reflect the irreducible structure of goal-directed cognition.

ACT-R: The Production System Blueprint

John Robert Anderson’s ACT-R (Adaptive Control of Thought, Rational) is a cognitive architecture developed at Carnegie Mellon that models human cognition as a production system [7]. It has three core components: declarative memory (stored facts and knowledge), procedural memory (if-then production rules that govern behavior), and a pattern matcher that selects which production to fire based on the current state and expected utility.
This maps cleanly to agentic AI reasoning loops. An agent’s context window and retrieved knowledge function as declarative memory. Its instructions, system prompts, and behavioral rules function as procedural memory. And its action selection process (choosing which tool to call, which sub-agent to invoke, which strategy to pursue) is utility-based pattern matching.
ACT-R’s central finding is that every task a human performs consists of a series of discrete, irreducible cognitive operations [7]. Each operation retrieves relevant knowledge, matches it against the current situation, and fires the highest-utility production. This is precisely what happens in an agentic reasoning loop: perceive context, match patterns, select action, execute. The iterative, multi-step nature of agentic workflows isn’t an engineering preference. It’s a cognitive necessity.

Recognition-Primed Decision Making: Why Reflection Works

Gary Klein’s Recognition-Primed Decision (RPD) model, developed through studying how fireground commanders make decisions under extreme pressure, reveals something counterintuitive about expert decision-making [8]. Experts don’t compare options analytically. They recognize situational patterns from experience, mentally simulate a course of action, and if the simulation succeeds, they execute. If it fails, they modify and simulate again.
This is the reflection pattern in agentic AI. When an agent generates output, evaluates it against criteria, identifies problems, and iterates, it follows the exact cognitive sequence Klein documented in human experts. The RPD model explains why reflection produces such surprising performance gains. Ng noted that even simple self-critique implementations dramatically improve output quality [1]. Reflection works because it mirrors the cognitive process that distinguishes expert performance from novice performance: the ability to simulate outcomes before committing to action.
The RPD model also predicts when reflection will fail. Mental simulation depends on having accurate mental models of the domain. When an agent lacks sufficient context, or its training data doesn’t cover the problem space, reflection loops degenerate into confident-sounding confabulation. Klein’s framework gives architects a diagnostic: if your agent’s reflection cycles aren’t improving output, the problem isn’t the loop. It’s the model’s domain knowledge.

Distributed Cognition: The Multi-Agent Blueprint

Edwin Hutchins’ distributed cognition theory, developed through studying navigation teams aboard Navy ships, argues that cognition doesn’t happen exclusively inside individual heads [9]. It extends across people, tools, artifacts, and environments. The unit of analysis isn’t the individual thinker. It’s the entire cognitive system.
This directly explains why multi-agent collaboration works. When you distribute a complex task across specialized agents (a researcher, a writer, an editor, a fact-checker), you distribute cognitive load across a system in exactly the way Hutchins described. Each agent handles a cognitive sub-function that would overwhelm a single agent’s context and reasoning capacity. David Kirsh’s work on coordination and environment design [10] extends this: the structure of the workflow itself (how agents pass information, what artifacts they create, how they signal state) is part of the cognitive architecture.
Multi-agent collaboration isn’t just an engineering convenience for managing complexity. It’s a fundamental principle of how complex cognition operates. Hutchins’ theory also predicts the failure mode that plagues poorly designed multi-agent systems: when coordination mechanisms between agents break down, the distributed cognitive system fails, even if each individual agent performs well in isolation.
If you’re interested in how these cognitive principles play out in practical human-AI collaboration scenarios, Human*AI Augmented Decision Making: What It Actually Looks Like explores the applied side of this research.

What This Means for Anyone Building Agents

The convergence between cognitive science and agentic AI isn’t academic trivia. It’s a design resource.
Every one of Ng’s four agentic design patterns has a cognitive science precedent that predicts not just when it will work, but when and why it will fail. GOMS tells you that task decomposition must be hierarchical and goal-structured, not flat lists of steps. ACT-R tells you that action selection depends on the quality of the agent’s “declarative memory” (its context and retrieved knowledge). Klein’s RPD model tells you that reflection only improves output when the agent has sufficient domain models to simulate accurately. Hutchins tells you that multi-agent coordination artifacts matter as much as the agents themselves.
The architects building the most robust agentic systems aren’t necessarily the ones with the fanciest models. They’re the ones who, whether they realize it or not, apply the same structural principles cognitive science established decades ago. The question is whether you want to rediscover those principles through trial and error, or start with the blueprint.

A Practical Definition Architects Can Use

Here is an agentic workflow defined through its cognitive foundations:

An agentic workflow is a goal-directed system that decomposes complex tasks into cognitive operations (perception, reasoning, action, evaluation), distributes those operations across specialized agents or modules, and iterates through reflection cycles that mirror human expert decision-making.

This definition gives you three design tests for any agentic system you build:

  1. Cognitive clarity. Does each agent or module have a clear cognitive role? Can you name what it perceives, what it reasons about, what actions it takes, and what it evaluates?
  2. Reflection integrity. Are reflection cycles built into the workflow architecture, not bolted on as an afterthought? Does the reflecting agent have sufficient domain knowledge to simulate outcomes accurately?
  3. Distributed coherence. Is cognitive load distributed appropriately across agents? Are the coordination mechanisms (handoff artifacts, state signals, shared context) as well-designed as the agents themselves?
    If you can answer yes to all three, you’re building on the same structural foundations that support expert human cognition. If you can’t, now you know where to look.
