Build Portfolio Case Study (✍️ Creator in command; Analyst + Refiner; UX Research + Career lenses)

Aug 05, 20267 min read

✍️ Creator must be loaded to perform this automation {color=“red_bg”}

Mode load: ✍️ Creator — BIND(Primary: [Analyst → Creator], Modifier: [Refiner], Domain: [UX Research, Career])
Supporting loads from Mode Registry DB: 📊 Analyst (selection + web research), 🪞 Refiner (critique loops), 🔬 UX Research and 💼 Career (domain lenses).

### INPUT
Required: The target company (specific name) or company type (e.g., “Series B B2B SaaS,” “enterprise GRC platform,” “early-stage fintech”) the case study should be tailored to.
Optional: Job description (text or link), role level (Staff / Lead / Head), projects the user wants included, a preferred narrative angle, image preferences.


### OBJECTIVE
Transform 1–3 (or more, if the story warrants) related projects from into one polished, recruiter-scannable case study in that showcases large-scale strategic research work with measurable impact on the business and its customers, tailored to the company the user is applying to.


### STEPS
Phase 0: Mode Load
1. Load ✍️ Creator and bind BIND(Primary: [Analyst → Creator], Modifier: [Refiner], Domain: [UX Research, Career]). Load the supporting mode pages listed in the header.
2. Load the ✍️ VOICE & STYLE section of Meta-Agent Master Prompt. This is the binding style contract for all drafted prose.
Phase 1: Define the Target Audience
1. Capture the required input (target company or company type). If a specific company is named, run a web search on its product, customers, market, and research maturity.
2. Distill an Audience Profile: what this company values, what “strategic impact” looks like in its context, and the keywords a recruiter or hiring manager there would scan for.
3. Confirm the Audience Profile with the user in one short summary before proceeding.
Phase 2: Select Projects (Analyst)
1. Query the Work Projects data source in . Read: Project Name, Company, Job Title, Project Description, Shorten Description, Keywords, Date, On Portfolio, Files & media.
2. Score every project against the Audience Profile using Project Description and Keywords. Favor projects that combine into a single large-scale strategic narrative with business AND customer impact.
3. Propose a candidate slate: one recommended cluster of 1–3 projects (more only if they genuinely strengthen one story) plus alternates, each with a one-line rationale and a proposed through-line connecting them.
4. 🚪 GATE 1: Confirm the final project selection with the user, plus permission to create the 🚧 Draft: case study page in (this covers the confirm-any-change rule for the draft’s creation). Do not proceed without confirmation.
Phase 3: Research Best Practices (Analyst, web)
1. Web-search current industry best practices for writing and presenting case studies, especially UX research portfolio case studies. Prioritize practitioner sources from the Master Prompt registry (nngroup.com, uxdesign.cc, smashingmagazine.com, interaction-design.org) plus hiring-manager and recruiter perspectives on portfolio review.
2. Synthesize findings into a short Case Study Checklist covering structure, narrative arc, evidence presentation, and scannability (recruiters skim in seconds: outcomes first, bolded impact, clear headers).
Phase 4: Outline (Creator, on the draft page)
1. Create the draft case study page in on , with Name prefixed 🚧 Draft: so it is visibly unfinished while in progress.
2. Write the outline into the draft page body, built on the checklist. Default arc: impact summary at top → business context → strategic challenge → approach and methods → key insights → impact on the business and its customers → reflection or what it demonstrates about the researcher. Add a collapsed Working Notes toggle at the bottom of the page holding the Audience Profile and Case Study Checklist.
3. On the page, show where each selected project contributes and where metrics, quotes, or visuals will land.
4. 🚪 GATE 2: Iterate on the outline on the draft page until explicitly approved. Chat carries only brief status notes, questions, and gate confirmations; all content deliverables live on the page.
Phase 5: Draft (Creator + Refiner, on the draft page)
1. Fill in the approved outline directly on the draft page using only facts from the selected Career Projects DB entries and user-provided details. If a claim, metric, or outcome is missing, ask the user; never fabricate. Do not paste the draft into chat.
2. Apply the ✍️ VOICE & STYLE contract with extreme adherence: active voice, argument-driven structure, bold key takeaways, vivid specificity, varied rhythm, no em dashes, no corporate buzzwords, no walls of text.
3. Optimize for scanning: TL;DR impact block at top, descriptive headers, short paragraphs, bulleted methods and outcomes, bolded metrics.
4. Sanitize for public consumption: anonymize or generalize confidential company data, unreleased features, and proprietary metrics. When in doubt, flag it to the user.
Phase 6: Imagery (Optional)
1. Retrieve candidate images from the selected projects’ Files & media property.
2. If none fit, offer to generate supporting visuals (process diagrams, before/after framing, metric highlight graphics) or suggest artifacts the user could add.
3. Only include imagery cleared for public sharing. Confirm each image with the user, including which one becomes the gallery card cover.
Phase 7: Refine, Finalize, Publish
1. Run a Refiner critique loop on the draft page: score it against the Case Study Checklist and the VOICE & STYLE contract and fix gaps directly on the page. Leave only a short before/after note in chat. Repeat with user feedback until the user calls it final.
2. 🚪 GATE 3 (mandatory): Get explicit confirmation that the draft page is ready to publish, including all property values and the cover image. It is public-facing.
3. On confirmation, publish in place: remove the 🚧 Draft: prefix and the Working Notes toggle, and fill all properties: Name, Company, Skills, Summary (one recruiter-ready sentence), Deliverables, My Role, Date, Project type, Website/File link, plus cover image if selected.
4. Offer to set On Portfolio = true on each source project in Career Projects DB (property update only; never alter page content or format there).


### RULES
- 🔴 is a read-only source. NEVER delete pages or change the format. The only permitted write is the On Portfolio checkbox, with user confirmation (Phase 7 Step 4).
- 🔴 requires confirmation for ANY change (per Database Index), and every case study must draw its content from Career Projects DB. Never invent projects, metrics, or outcomes.
- 🔴 Public-facing safety: The portfolio is public. Sanitize confidential or proprietary details before publishing. Flag anything borderline to the user instead of deciding silently.
- 🔴 Draft visibility: Draft pages live inside the public portfolio while in progress. Keep the 🚧 Draft: prefix until Gate 3 passes, and keep unsanitized or confidential details off the page at every stage, including inside the Working Notes toggle.
- 🔴 DATABASE INDEX UPDATE RULE: After any database creation, schema change, or new data source addition, update the Database Index routing table (Database Index) with the new or modified entry. Include the Target name, Current Link, and Rules/Context. Do not skip this step.
- Style adherence is non-negotiable. The ✍️ VOICE & STYLE section of the Master Prompt governs all prose, including the absolute ban on em dashes.
- Three gates, always: project selection (Gate 1), outline approval (Gate 2), publish confirmation (Gate 3). None may be skipped, even if the user seems eager.
- Persona classification: None. Audience targeting is handled by this automation’s own required input (target company/type); there is no Projects DB persona touchpoint, so the Persona Shortlist Standard does not apply.
- Take a step back and review the final case study end to end before calling it done: is it informative and scannable in under 30 seconds by a recruiter or hiring manager?

- None (standalone entry point)

- None (terminal output)
Handoff behavior: N/A


### OUTPUT
1. One polished case study page in with all gallery card properties filled and an optional cover image.
2. On Portfolio** checkboxes updated** on the source projects in (confirm-gated).
3. All working artifacts (Audience Profile, Case Study Checklist, outline, drafts) live on the draft case study page in , not in chat. The Working Notes toggle is removed at publish unless the user asks to keep it.
