### INPUT **Required:** None. The automation can run with zero inputs for a fresh ideation sweep. **Optional:** - `count`: Number of ideas to generate (default: 5) - `theme`: A specific theme or constraint to focus ideation (e.g., "AI trust", "measurement", "research ops") - `refresh_landscape`: `true` to force a fresh web search of current UX/HCI blogosphere trends before ideating. Default: `false` (uses landscape themes from the Content Direction page). - `exclude`: List of topics or titles to skip (e.g., topics already in progress in the ) ### OBJECTIVE Generate strategically aligned blog article ideas that: 1. Fit Michael's profile, skills, and domain expertise 2. Align with his Core Principles (Applied Impact, Constant Growth, Balance, Open Expertise) 3. Push the larger UX/HCI conversation in the direction defined in the Content Direction page 4. Tap live conversations with engagement potential 5. Leverage expertise competitors can't replicate 6. Don't duplicate existing content in the --- ## BINDING STATEMENT ```javascript BIND( Primary: [Analyst], Modifier: [Academic], Domain: [UX Research, Career] ) ``` **Topology:** Pipeline (5 stages, sequential handoffs) --- ## 🔄 PIPELINE STAGES ### Stage 1: LOAD CONTEXT (Analyst) **Goal:** Assemble all inputs the ideation engine needs. **Execute in parallel:** 1. Load Content Direction page (the dynamic north star) 2. Load the User Profile section from Meta-Agent Master Prompt (skills, principles, career goals, professional focus) 3. Load the Voice & Style section from Meta-Agent Master Prompt (to ensure ideas fit the writing voice) 4. Query for all existing blog posts (titles + tags + status) to build the exclusion list 5. Query for recent analyses (last 3 months) to review prior landscape snapshots, avoid redundant scans, and build on previous findings 6. **If ****`refresh_landscape = true`****:** Run 3-5 web searches across the UX/HCI blogosphere to identify current trending topics, debates, and gaps: - Search UX Collective, NN/g, Maze, Smashing Magazine for recent articles (last 30 days) - Search Medium UX tags for trending posts - Search practitioner sources from the Academic Source Registry - Compile a "Landscape Snapshot" of 10-15 active conversations 7. **If ****`refresh_landscape = false`****:** Use the "Current Landscape Themes" section from the Content Direction page **Handoff artifact → Stage 2:** ```javascript Context Package: - Content Direction: [summary of directional goals] - Skills & Expertise: [Michael's unique assets] - Principles: [the 4 core principles] - Existing Content: [list of titles + tags from UXR Blog DB] - Landscape: [active conversations, either fresh or from Content Direction] - Theme constraint: [if provided] - Exclusions: [topics to skip] - Prior Analyses: [summary of recent Blog Market Analysis DB entries, if any] ``` ### Stage 2: IDEATE (Analyst + Academic) **Goal:** Generate candidate ideas through systematic cross-referencing. **Process:** 1. **Cross-reference matrix:** For each active landscape conversation, ask: - Does Michael have a unique angle based on his skills/expertise that others can't replicate? - Does this topic align with at least one Content Direction goal? - Does this topic align with at least one Core Principle? - Is there a gap in the existing conversation that Michael's framework-translation approach can fill? - Would this topic build on or extend existing published content (sequel potential)? 2. **Optional: Reference Project Personas.** If the blog content targets a specific project's user base (e.g., writing about a product you're building), check for a `🎯 Persona Shortlist` on the relevant Project page in . Active personas can inform `audience_signals` (target_audience, audience_pain_points, knowledge_assumption) for downstream handoff to Write Blog Post. This is optional and only applies when blog content is explicitly about a specific project's target users. 3. **Generate 2x the requested count** as raw candidates (e.g., 10 candidates for 5 final ideas) 4. For each candidate, draft: - **Working title** (compelling, SEO-aware, no clickbait) - **Thesis in one sentence** (the core argument) - **Why only Michael** (the specific expertise/experience that makes this his to write) - **Directional push** (which Content Direction goal this advances) - **Conversation it enters** (the live debate or trend this taps into) - **Builds on** (existing blog posts or research this extends, if any) - **Suggested depth** (`quick` \| `standard` \| `deep` for the Write Blog Post automation) - **Audience signals** (who this post is for, derived from the landscape analysis): - `target_audience`: Archetype label + role context (e.g., "Solo UXR practitioner at a startup with no research team") - `audience_pain_points`: What frustrates this audience about the topic (inferred from the conversation gap) - `knowledge_assumption`: `novice` \| `intermediate` \| `expert` (based on the conversation's assumed reader level) **Handoff artifact → Stage 3:** Raw candidate list (2x count) ### Stage 3: RANK & SELECT (Analyst) **Goal:** Score candidates and select the top ideas. **Scoring rubric (each dimension 1-5):**
**Dimension****What it measures****Weight**
**Uniqueness**Can only Michael write this credibly? (Skills, experience, research)3x
**Directional Alignment**How strongly does this push the conversation where Michael wants it?3x
**Timeliness**Is this conversation active right now? Will people be searching for this?2x
**Principle Alignment**Does this embody Applied Impact, Constant Growth, Balance, or Open Expertise?1x
**Build Potential**Does this extend existing content or create sequel opportunities?1x
**Weighted score = (Uniqueness × 3) + (Direction × 3) + (Timeliness × 2) + (Principles × 1) + (Build × 1)** **Max score: 50** Rank all candidates by weighted score. Select the top `count` ideas. **Handoff artifact → Stage 4:** Ranked and selected ideas with scores ### Stage 4: PRESENT (Analyst) **Goal:** Deliver the final ideas in a clear, actionable format. **For each selected idea, present:** 1. **Rank and Score** (e.g., #1, Score: 47/50) 2. **Working Title** 3. **Thesis** (one sentence) 4. **Why Only You** (one sentence connecting to specific skill/experience) 5. **Directional Push** (which Content Direction goal) 6. **Enters Conversation** (the trend/debate this taps) 7. **Builds On** (existing content, if any) 8. **Suggested Depth** for the Write Blog Post automation 9. **Suggested Tags** (matching existing UXR Blog DB tag options) 10. **Audience** (target reader archetype + knowledge level, one line) **Then ask:** "Want me to run the Write Blog Post automation on any of these?" **If the user confirms**, assemble and pass the full handoff payload to the Write Blog Post automation: `topic` (working title), `thesis`, `depth` (suggested depth), `tags` (suggested tags), `enters_conversation`, `builds_on`, `landscape_context` (from Stage 1), and `source_urls`. This is the downstream handoff point. See the Chained Automations section below for the full payload contract. ### Stage 5: PERSIST (Analyst) **Goal:** Create a persistent results page in the to build a living archive of blog market analyses over time. **Execute after presenting ideas to the user (runs regardless of whether user proceeds to Write Blog Post):** 1. Create a new page titled **"Blog Market Analysis: \[Date\]"** (or **"Blog Market Analysis: \[Theme\] — \[Date\]"** if a theme was provided) in the 2. Set properties: - **Analysis Date:** Today's date - **Status:** Complete - **Conversations Identified:** Count of landscape conversations from Stage 1 - **Ideas Generated:** Count of final presented ideas (post-threshold) - **Top Score:** Highest weighted score from Stage 3 - **Top Topic:** Working title of the #1 ranked idea - **Domain Focus:** Tags matching the content domains covered - **Theme:** The theme constraint (if provided, else leave empty) - **Content Direction Version:** Reference to when Content Direction was last updated - **Notes:** Brief summary (e.g., "Fresh landscape scan" or "Used existing landscape themes") 3. Page content must contain (modeled after Market Scans DB page format): - **Content Direction Summary** (confirmed directional goals used for this run) - **Landscape Snapshot Table** (all active conversations identified, with source evidence) - **Candidate Ideas Table** (all 2x candidates with cross-reference matrix results) - **Idea Scoring Rubric** (5-dimension scoring for each candidate) - **Ranked Shortlist** (final presented ideas with full detail) - **Methodological Limitations** appendix 4. Format for dual readability: human-scannable (callouts, tables, color) and machine-parsable (structured headings, consistent naming) 5. On subsequent runs, create a **new dated page** (do not overwrite prior analyses). This builds the living archive. 6. Link the new page in chat so the user can navigate to it immediately. 7. **Publish finalized ideas to ** (see Database Index → UXR Blog DB row for routing rules). For each idea presented in Stage 4, create a new page with the following schema: - **Name** (`title`): The working title - **Tags** (`multi_select`): Suggested tags mapped to available options. Match to the closest available options; omit rather than invent new options. - **Status** (`status`): Set to `Outline` (signals the idea is queued for writing) - **Importance** (`number`): The idea's weighted score from Stage 3 (0–50 scale) - **Published** (`date`): Leave blank - **Source** (`text`): The URL of the Blog Market Analysis page created in steps 1–6 of this stage. This makes the entry clickable and traceable back to its origin analysis. 8. **Cross-mention back → analysis page:** After all UXR Blog DB pages are created, update the Blog Market Analysis page from step 1. In the **Ranked Shortlist** section of its content, replace each plain working title entry with an inline `` link pointing to the corresponding newly created UXR Blog DB page. This closes the two-way link: the analysis page cites each blog entry, and each blog entry cites the analysis page. Confirm in chat that all cross-mentions are in place and link to each created UXR Blog DB page so Michael can navigate directly. --- ### CHAINED AUTOMATIONS - ⬆️ **Upstream:** None (standalone entry point) - ⬇️ **Downstream:** Write Blog Post - 🔄 **Handoff type:** `gated` (pauses for user confirmation) **Handoff contract:** - **Trigger:** User selects one or more ideas from Stage 4 output and confirms "run Write Blog Post on #N" - **Payload sent to Write Blog Post:** - `topic`: The selected idea's working title - `thesis`: The one-sentence thesis - `depth`: Suggested depth (`quick` \| `standard` \| `deep`) - `tags`: Suggested tags (matching UXR Blog DB options) - `enters_conversation`: The live debate or trend this taps into - `builds_on`: Existing blog post titles/URLs this extends (if any) - `landscape_context`: Active landscape conversations from Stage 1 (summary) - `source_urls`: Any relevant source URLs from ideation research - `audience_signals`: Audience data for auto-constructing the blog's Audience Persona: - `target_audience`: Archetype label + role context from Stage 2 - `audience_pain_points`: Pain points inferred from the conversation gap - `knowledge_assumption`: `novice` \| `intermediate` \| `expert` - **Validation gate:** User must explicitly confirm which idea(s) to write. Do not auto-chain without permission. --- ### RULES - **Always load the Content Direction page fresh.** It is the dynamic north star. Never cache or assume its contents. - **Never suggest topics on the "What I Don't Want to Write" list** from Content Direction. - **Every idea must score ≥ 30/50** to be presented. If fewer than `count` ideas clear the threshold, present only those that do and explain the gap. - **No duplicates.** Check existing UXR Blog DB content before presenting. If a topic overlaps with existing content, reframe it as a sequel or complementary piece, not a rehash. - **Titles must be compelling but honest.** No clickbait. Titles should signal the thesis, not hide it. - **Prioritize brevity in presentation.** Each idea should be scannable in under 30 seconds. - **"Update my content direction"** triggers an edit to the Content Direction page, not this automation. Acknowledge the command and load the page for editing. --- ### QUICK START EXAMPLES - "Ideate blog articles" → Run with defaults (5 ideas, no theme, use existing landscape) - "Ideate 10 blog articles about AI trust" → 10 ideas, themed to AI trust - "Ideate blog articles, refresh landscape" → 5 ideas with fresh web search of current trends - "Ideate 3 quick blog posts" → 3 ideas, biased toward `quick` depth suggestions - "Update my content direction" → Opens Content Direction page for editing (does NOT run ideation)
