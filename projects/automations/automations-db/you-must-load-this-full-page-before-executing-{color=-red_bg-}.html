BINDING STATEMENT

Topology: Pipeline (4 stages, sequential handoffs)

### INPUT **Required:** - `topic`: The L&L session topic (working title or description) **Optional (auto-populated when chained from Ideate L&L Topics):** - `core_claim`: The one-sentence core claim - `audience_persona`: Full PED Audience Persona schema - `means_inventory`: Presenter's teaching means - `teaching_opportunity`: Framework lens + reasoning from ideation - `nudge_goal`: The desired behavior change - `format`: Session format (talk / workshop / hybrid / discussion) - `ideation_page_url`: URL of upstream ideation page **Standalone inputs (when not chained):** - `audience_context`: Additional context about the PED audience - `depth`: `standard` (default) \| `deep` (more sources, wider search) ### OBJECTIVE Build the complete evidence base for a L&L session: 1. **Academic grounding** — peer-reviewed evidence supporting the core claim 2. **Practical/business grounding** — real-world case studies, industry examples, and business impact data that make the academic evidence tangible for PED professionals 3. **Inoculation brief** — preemptive objection handling with evidence-based rebuttals 4. **Refined audience persona** — updated with research-informed insights about what the audience actually needs to hear Every claim the presenter will make in the session must trace to a source from this phase. --- ## 🔄 PIPELINE STAGES ### Stage 1: FRAME THE EVIDENCE NEED (Analyst) **Goal:** Define exactly what evidence is needed before searching. **If chained from Ideate L&L Topics:** 1. Load the upstream ideation page to recover full context 2. Load the 🎤 PED Lunch & Learn Designer mode page (persuasion architecture, narrative arc) 3. Use the `core_claim`, `teaching_opportunity`, and `nudge_goal` to define the evidence search space **If standalone:** 1. Load User Profile from Meta-Agent Master Prompt 2. Load the 🎤 PED Lunch & Learn Designer mode page 3. Infer the core claim, teaching opportunity, and nudge goal from the topic 4. If no audience persona provided, infer one (see Persona Protocol below) **Define the evidence search plan:** - **Core claim to prove:** \[the central argument\] - **Supporting claims needed:** \[2-3 sub-arguments that build the case\] - **Practical translation needed:** \[what real-world examples would make this tangible for PED?\] - **Likely objections to inoculate against:** \[based on audience persona's "Likely Resistance"\] **Handoff → Stage 2:** Evidence search plan ### Stage 2: ACADEMIC RESEARCH (Analyst + Academic) **Goal:** Build the scholarly evidence base using the Academic Source Registry. **Execute parallel web searches across Academic Source Registry domains:** - `scholar.google.com`, `semanticscholar.org`, `arxiv.org`, `dl.acm.org`, `openalex.org` - Domain-specific sources based on topic (see Academic Source Registry in Master Prompt) **Source targets by depth:** - `standard`: 5-8 peer-reviewed sources - `deep`: 10-15 peer-reviewed sources **Prioritize:** meta-analyses \> RCTs \> experimental studies \> qualitative studies \> expert opinion **Focus domains:** HCI, cognitive psychology, organizational behavior, learning science, product management, behavioral economics **For each source, extract:** - Full APA citation - Key finding (1-2 sentences) - Study type and sample (for credibility assessment) - Quotable conclusion (for the presenter to use directly) - **Which session phase it serves** (Problem Frame / Academic Authority / Reframe / Tactical Translation / The One Thing) - **Evidence tier** (following Market Evaluation Scoring Kit taxonomy: Behavioral \> Declared \> Hypothetical) **Handoff → Stage 3:** Academic Evidence Brief ### Stage 3: PRACTICAL & BUSINESS GROUNDING (Analyst) **Goal:** Make the academic evidence tangible with real-world cases that PED professionals recognize and respect. **This is not optional. Academic evidence alone does not persuade PED audiences. The practical grounding is what makes them believe it applies to *their* work.** **Search for 3-5 industry examples across three tiers:** **Tier 1: Household Name Cases (credibility anchors)** - Search for how major tech companies (Google, Apple, Airbnb, Spotify, IBM, Microsoft, IDEO) have applied the session's core principle - These are not proof, they are credibility shortcuts (peripheral route, per ELM) - Best used in Phase 1 (Problem Frame) and Phase 2 (Academic Authority) **Tier 2: Peer-Scale Cases (relatability anchors)** - Search for mid-market or B2B companies that applied the principle in contexts similar to the audience's own work - These prove "this works for teams like yours, not just Google" - Best used in Phase 4 (Tactical Translation) **Tier 3: Business Impact Data (ROI anchors)** - Search for quantified business outcomes: revenue impact, time saved, defect reduction, NPS improvement, churn reduction tied to the session's principle - These answer the unspoken question: "Why should I care about this academically?" - Best used in Phase 1 (Problem Frame) and Phase 3 (Reframe) **For each example, extract:** - Source and URL - Company/team context - What they did (the specific application) - What happened (the measurable outcome) - **Which session phase it serves** - **Why PED should care** (the bridge statement connecting this to their daily work) **Handoff → Stage 4:** Practical Grounding Brief ### Stage 4: INOCULATION ANALYSIS + PERSONA REFINEMENT + PERSIST (Analyst) **Goal:** Complete the evidence package with objection handling, refine the persona, and persist everything. **Inoculation Analysis:** Using the audience persona's "Likely Resistance" field + the evidence gathered: 1. Identify 3-5 likely objections the PED audience will raise (or think silently) 2. For each objection: - **The objection** (stated in the audience's own language) - **Why it feels true** (validate the concern, don't dismiss it) - **The evidence-based rebuttal** (cite specific academic or practical source) - **The bridge statement** (how to transition from acknowledging the objection to presenting the reframe) 3. Rank by likelihood of surfacing during the session **Persona Refinement:** Update the audience persona with research-informed insights: - **Refined knowledge level:** Based on what the research revealed about typical PED understanding of this topic - **Updated resistance map:** Now grounded in specific evidence gaps, not just assumptions - **Emotional register:** What emotions does this topic trigger? (defensiveness, curiosity, skepticism, excitement) - **Language cues:** Specific terms, metaphors, or framings that will resonate with this audience based on the practical examples found **Persist as a Notion page:** 1. Create a page titled **"🔬 L&L Research Brief: \[Topic Title\]"** 2. Route per Organizing Rules 3. Page content must contain: - **Evidence Search Plan** (what we set out to find) - **Academic Evidence Table** (all sources with APA citations, key findings, session phase mapping, evidence tier) - **Practical Grounding Table** (all industry examples with context, outcomes, session phase mapping) - **Inoculation Brief** (all objections with rebuttals and bridge statements, inside a callout) - **Refined Audience Persona** (full updated schema, inside a toggle for easy access) - **Evidence Gaps** (what we couldn't find, what would strengthen the case) - **Full APA Source List** 4. **Cross-link:** If chained from Ideate, add a mention-link back to the ideation page. Update the ideation page's shortlist entry with a mention-link to this research brief. **In chat, present:** - Evidence summary (count of academic + practical sources) - Top 3 strongest pieces of evidence - The #1 likely objection and its rebuttal - The refined persona (1-line summary of what changed) - Link to the persisted research brief page **Then ask:** "Want me to run the **Build L&L Presentation Outline** automation to structure this into a presentation?" --- ### PERSONA PROTOCOL **When chained from Ideate L&L Topics:** The persona arrives in the handoff payload. Use it as the starting point and refine it in Stage 4. **When standalone (no upstream persona):** Infer a persona after Stage 1 using: - The topic domain (which PED roles care most about this?) - User-provided `audience_context` - General PED archetype patterns - Present the inferred persona for user confirmation before proceeding to research **Persona schema (same as Ideate automation for chain consistency):** ```javascript Persona Name: [archetype label] Role Mix: [primary PED roles for this topic] Current Mental Model: [what they currently believe] Knowledge Level: [novice | intermediate | advanced] Likely Resistance: [the objection they'll raise] Desired End State: [what they should believe/do after] ELM Route: [peripheral | central] ZPD Position: [can do now vs. could do with scaffolding] --- (added in Stage 4 refinement) --- Emotional Register: [emotions this topic triggers] Language Cues: [terms and framings that resonate] ``` **Personas are persistent artifacts.** They are embedded in every output page and flow to downstream automations. --- ### CHAINED AUTOMATIONS - ⬆️ **Upstream:** Ideate PED L&L Topics (Analyst in command, Academic + UX Research) - ⬇️ **Downstream:** Build PED L&L Presentation Outline (Creator in command, Narrative Architect + Refiner) - 🔄 **Handoff type:** `gated` (pauses for user confirmation) **Handoff contract (receiving from Ideate L&L Topics):** - `topic`: Selected working title - `core_claim`: One-sentence core claim - `audience_persona`: Full persona schema - `means_inventory`: Presenter's teaching means - `teaching_opportunity`: Framework lens + reasoning - `nudge_goal`: Desired behavior change - `format`: Suggested format - `ideation_page_url`: URL of ideation page **Handoff contract (sending to Build Presentation Outline):** - `topic`: Session title - `core_claim`: Refined core claim (may have evolved during research) - `audience_persona`: Refined persona (with emotional register + language cues) - `academic_evidence`: Summary of academic sources with session phase mapping - `practical_evidence`: Summary of industry examples with session phase mapping - `inoculation_brief`: All objections with rebuttals and bridge statements - `nudge_goal`: Desired behavior change - `format`: Session format - `means_inventory`: Presenter's teaching means (for authority calibration) - `research_page_url`: URL of the persisted research brief page - `ideation_page_url`: URL of upstream ideation page (if chained) --- ### RULES - **Every claim must trace to a source.** No unsupported assertions in the research brief. - **Practical grounding is mandatory, not optional.** Academic evidence without real-world cases will not persuade PED. - **Classify all evidence by tier** (Behavioral \> Declared \> Hypothetical). Cap confidence claims by the highest tier available. - **Inoculation Analysis must run before the research brief is complete.** Objections inform which evidence gaps matter most. - **Persona refinement is mandatory.** The persona must be updated with research insights before handoff. - **Always persist output as a Notion page.** No exceptions. - **Cross-link to upstream artifacts** when chained. - **Use the Academic Source Registry by reference** from the Master Prompt. Do not hardcode domain lists. - **Voice & Style from Master Prompt governs all written output.** --- ### QUICK START EXAMPLES - "Research the JTBD lunch and learn topic" → Standard depth, uses upstream topic - "Ground this L&L topic in evidence" → Same trigger, full pipeline - "Deep research on cognitive load for PED" → Deep depth, standalone - "Find evidence for why user research should happen before sprint planning" → Standalone, infers persona
