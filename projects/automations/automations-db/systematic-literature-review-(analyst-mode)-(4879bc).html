### INPUT **Required:** A research question, topic, or set of keywords. **Optional:** - `depth`: `quick` \| `standard` (default) \| `exhaustive` - `domain`: HCI, UXR, psychology, management, health, etc. (determines secondary database selection) - `timeframe`: Publication date range filter (e.g., "last 5 years") - `output_format`: `summary` (default) \| `annotated_bibliography` \| `full_report` - `max_sources`: Target number of final included sources (default: 15 for quick, 30 for standard, 50+ for exhaustive) ### OBJECTIVE Perform a systematic, reproducible literature review following PRISMA 2020 guidelines adapted for AI-assisted web search. Uses a finite-state machine protocol with keyword expansion, citation chaining, and author network tracing to maximize discovery within the real constraints of web-based search tools. **All results are always persisted to the Academic Research databases.** No exceptions, no "offer to create." This happens automatically at S5/S6 (or at the end of the quick bypass). --- ## 🗃️ DATA ROUTING (hardcoded for speed) ### Target Data Sources **Research Projects:** - One entry per lit review (the project itself) - Research Type: `Literature Review` - Synthesis, gap analysis, and search strategy go in the **page content** - Status: `Synthesis` (or `Writing` if producing a full report) **Literature Library:** - One entry per included paper - Link each entry to the Research Project via `Related Projects` relation - Map extracted data to properties:

Restate the user's research question(s) in structured form 2. Define **inclusion criteria**: publication type, date range, language, domain 3. Define **exclusion criteria**: grey literature, non-peer-reviewed, duplicates, off-topic 4. Determine **depth level** from user input or default to `standard` 5. Identify the **domain** to select secondary academic databases from the **Academic Source Registry** in the Meta-Agent Master Prompt 6. Output scope definition to the user for confirmation (unless user said "just do it") **Transition → S1** when scope is confirmed or defaults accepted. --- ### S1: KEYWORD GENERATION **Goal:** Build a comprehensive, unbiased search strategy. 1. Extract **primary terms** from the research question 2. Generate **synonyms and related terms** for each primary term: - Academic synonyms (e.g., "usability" → "ease of use", "user friendliness") - Broader terms (e.g., "card sorting" → "information architecture methods") - Narrower terms (e.g., "mental models" → "schema theory", "conceptual models") 3. Build **Boolean search strings** using AND/OR operators 4. Create **at least 3 query variations** targeting different facets of the topic 5. If the domain has controlled vocabularies (MeSH, ACM CCS), include those terms **Transition → S2** when search strings are ready. --- ### S2: DATABASE SEARCH **Goal:** Cast a wide net across academic sources. 1. Execute **parallel web searches** using the **Academic Source Registry** from the Meta-Agent Master Prompt: - Select **primary** (always) and **secondary** (domain-conditional) databases per the registry - Add **UX/HCI practitioner sources** when domain = UXR/HCI 2. Use `category: "research paper"` filter for peer-reviewed work 3. Run **each query variation** across **each database set** in parallel batches 4. Collect: title, authors, year, abstract snippet, source URL, citation count (when available) 5. Store results in a running **candidate list** (working memory) **Transition → S3** when all search batches complete. --- ### S3: SCREEN **Goal:** Remove duplicates and filter by relevance (single pass). 1. **Deduplicate** by matching on title similarity 2. **Screen** each paper against inclusion/exclusion criteria using available metadata (title, abstract, authors, venue, year) 3. **Score relevance** on a 3-point scale: - ✅ **Include**: Directly addresses the research question - 🟡 **Maybe**: Tangentially relevant, keep for now - ❌ **Exclude**: Off-topic, wrong population, wrong method, etc. 4. Record exclusion reasons and track counts: total found, duplicates removed, screened out, remaining **Transition → S4** (if `standard` or `exhaustive`) OR **→ S5** (if expansion rounds exhausted). --- ### S4: EXPAND (combined discovery state) **Goal:** Find papers that keyword search alone would miss. Run these substeps in order. **Substep A: Keyword Expansion** 1. From included papers, extract author keywords, recurring terms, and subject headings 2. Compare against your original keyword list 3. If new terms found, build new queries and flag for re-search **Substep B: Author Trace** (graph-query: author node traversal) 1. Identify the **top 3 most-recurring or most-cited authors** from included papers (top 5 + co-authors for `exhaustive`) 2. Search `"[Author Name]" + [topic keywords]` on Google Scholar and Semantic Scholar 3. Note co-authors who appear repeatedly (research cluster signal) 4. Screen newly discovered papers against inclusion criteria **Substep C: Backward Snowball** (graph-query: predecessors/incoming edges) 1. From accessible reference lists of included papers, identify: - Foundational/seminal works (frequently referenced across multiple included papers) - Methodologically relevant papers - Directly on-topic references based on title 2. Search for and screen these papers 3. Track bibliographic coupling: papers sharing many references with your included set are likely relevant **Substep D: Forward Snowball** (graph-query: descendants/outgoing edges) 1. For key included papers, search for papers that cite them: - Search `"[paper title]"` on Semantic Scholar (best for citation data) - Search `"[paper title]" cited` on Google Scholar 2. Prioritize recent citing papers (current state of the field) 3. Track co-citation patterns: if two papers are frequently cited together and you have one, search for the other **⚠️ See Constraints section.** Forward snowball via web search is approximate, not exhaustive. **Saturation Check (S4b):** 1. Count new unique papers added this round 2. If new papers found AND iterations \< max → **Transition → S3** (re-screen, then S4 again) 3. If no new papers OR iterations \>= max → **Transition → S5** **Max iterations:** `standard` = 1 cycle, `exhaustive` = until saturation or 3 cycles. --- ### S5: EXTRACT + SYNTHESIZE + PERSIST **Goal:** Pull structured data, make meaning, and save everything to the databases. **Step 1: Create the Research Project** 1. Create a page in with: - `Project Title`: descriptive title based on the research question - `Research Type`: Literature Review - `Status`: Synthesis - `Research Question(s)`: the original research question(s) from S0 - `Lead Researcher`: Michael ([user://dc829c30-727f-4bc2-b8cf-22431bfef9e9](user://dc829c30-727f-4bc2-b8cf-22431bfef9e9)) - `date:Start Date:start`: today's date 2. Save the project URL for linking Literature Library entries **Step 2: Dedup check** 1. Query the existing Literature Library for potential matches (see Dedup Protocol in Data Routing) 2. Note which papers already exist so you link rather than duplicate **Step 3: Create Literature Library entries** 1. For each included paper, create a page in following the field mapping in Data Routing 2. Set `Related Projects` to the Research Project URL from Step 1 3. Batch create in groups of 10 (tool limit) with parallel calls if needed 4. For papers that already exist (from dedup), update their `Related Projects` to add the new project **Step 4: Extraction** (for each included paper's page content, keep brief): - 2-3 sentence summary of methodology and approach - Key findings and relevance to the research question - Notable limitations - This goes in the **page content** of each Literature Library entry **Step 5: Synthesis** (this goes in the Research Project page content): 1. **Thematic analysis**: Group papers by theme, approach, or finding pattern 2. **Convergence/divergence**: Where do findings agree? Conflict? 3. **Chronological narrative**: How has the field evolved? 4. **Methodological assessment**: What methods dominate? What's underrepresented? 5. **Gap identification**: Unanswered questions, thin evidence areas 6. **Practical implications**: What this means for the user's specific context 7. **Key author mapping**: Leading voices and their positions **Transition → S6** when all entries are created and synthesis is written. --- ### S6: REPORT **Goal:** Finalize the Research Project page and deliver a chat summary. **On the Research Project page** (update content): 1.  --- ### CONSTRAINTS + LIMITATIONS (be honest about these) **What this protocol can do well:** - Cast a wide keyword net across multiple academic databases in parallel - Extract structured data from titles, abstracts, and metadata - Identify recurring authors and trace their other work by name search - Do backward snowballing when reference lists are visible in search results or accessible web pages - Synthesize themes, gaps, and convergence/divergence from available information **What this protocol does approximately (not perfectly):** - **Forward snowballing.** Web search for "papers citing X" is a keyword approximation, not true citation graph traversal. Semantic Scholar is the most reliable source for this, but coverage is inconsistent. Treat forward snowball results as supplementary, not comprehensive. - **Citation counts.** Available when search results surface them, but not guaranteed. Don't weight conclusions heavily on citation counts alone. - **Deduplication.** Based on title matching in reasoning, not algorithmic fuzzy matching. Some near-duplicates (e.g., preprint vs. published version) may slip through. - **Full-text assessment.** Often limited to abstracts and metadata. When full text isn't accessible, say so rather than guessing at methodology or findings. **What this protocol cannot do:** - Access paywalled full-text PDFs - Query citation databases programmatically (no API access to Semantic Scholar, OpenAlex, etc.) - Guarantee exhaustive coverage (web search has inherent recall limits) - Replace independent dual-reviewer screening (all screening judgments are single-agent) **Search flow counts are transparent, not "PRISMA-compliant."** Real PRISMA compliance requires independent reviewers and inter-rater reliability. The counts here document what happened during the search process for reproducibility and user verification, not for publication-grade methodological claims. --- ### RULES - **Use the Academic Source Registry by reference.** All database lists live in the Meta-Agent Master Prompt. Do not hardcode domain lists in this automation. - **Run parallel searches.** Batch independent queries across different databases simultaneously. - **Track search flow counts** at every state transition. The final report must include them. - **Do not fabricate citations.** Report what you can verify from titles, abstracts, and metadata. If you can't access full text, say so. - **Declare depth level upfront** and follow its constraints. Do not silently upgrade or downgrade. - **Stop expanding when returns diminish.** \< 2 new qualifying papers per round = saturated. - **Cite everything.** Every claim in the synthesis must trace to a specific paper. - **Flag bias.** Note if the literature is dominated by a single research group, geography, or methodology. - **If the user asks for a specific output location** (Notion page, database), create the artifact there. Otherwise, deliver in chat. ### OUTPUT (always created, all depths) **In Notion (persistent artifacts):** 1. **Research Project page** in containing: - Search flow summary, full synthesis, search strategy, recommended reading, gap analysis - Linked to all Literature Library entries via the `Sources` relation (auto-populated from the other side) 2. **Literature Library entries** in : - One per included paper with full metadata and key findings - Linked back to the Research Project via `Related Projects` - Page content has a brief methodology/findings summary for each paper **In chat (brief handoff):** 1.
