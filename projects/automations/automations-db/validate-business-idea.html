Validate Business Idea

Feb 07, 202611 min read

**YOU MUST BE IN ANALYST MODE TO PERFORM THIS AUTOMATION** --- ## Objective Take a raw business idea from the user, run it through a structured critical thinking framework grounded in Double Diamond + JTBD methodology, score it, and document the validated (or rejected) idea in the database. --- ## Trigger User says something like: "validate this business idea", "stress test this idea", "soundproof this idea", "evaluate this business concept" **Upstream triggers:** Can also be triggered from the Market Evaluation Scoring Kit or directly from Identify Market Populations to Innovate For (🧭 Market Population Identifier in command). Can also be triggered standalone with any business idea. --- ## Inputs Required Ask the user for: 1. **The idea** (one sentence minimum) 2. **Who it's for** (optional, you'll validate this) 3. **Any context** they already have (competitors, market size, personal experience) 4. **Project context** (optional): If this idea is tied to a Project in , load the Project page and check for a `🎯 Persona Shortlist` section. Active personas provide pre-validated target user data for Phase 1 Q1, skipping cold research on "who experiences this problem." If no Persona Shortlist exists but the user names a Project, offer to run Persist Persona Shortlist to Project (Analyst in command) after Phase 4. --- ## Execution Steps ### Phase 0: Theory Formation Before diving into research, ask the user to articulate their contrarian belief. Load Phase 0 questions: 1. **What is the commonly held belief (orthodoxy) in this space?** 2. **What do you believe that contradicts or goes beyond that orthodoxy?** 3. **What is your causal logic: if X, then Y, because Z?** 4. **What hidden latent need in this space might modern AI uniquely surface or solve — either because AI now makes the work cheap, or because it was technically infeasible before modern models?** If you cannot answer, surface candidates during Phase 1 (Q4.5) and circle back. This gives the entire downstream analysis a "search image" instead of open-ended exploration. If the user can't articulate a contrarian belief, help them find one through the Phase 1 research, then circle back. ### Phase 1: Problem Space (Discover + Define) Run through these questions using web search + reasoning. For each question, provide a **synthesized answer** (not a surface-level guess). **Classify all evidence by type** using the Market Evaluation Scoring Kit taxonomy (Market \> Behavioral \> Declared \> Hypothetical).
#QuestionWhat It Forces
**1****Who experiences this problem so acutely that they've already built workarounds?**Identifies desperate users with validated pain, behavioral evidence, and willingness to pay
**2****What do those workarounds reveal about the job they're actually trying to accomplish?**Surfaces the real need beneath stated needs, reveals evaluation criteria
**3****What existing solutions have failed them, and why?**Reveals competitive gaps and non-obvious barriers
**4****How large is the addressable population experiencing this at equal or greater intensity?**Quantifies market, validates economic viability
**4.5****What proprietary or fragmented data (support tickets, community workarounds, telemetry, peer-to-peer conversations, abandoned-feature signals, niche forum threads) could AI now analyze to reveal unmet needs invisible to incumbents?**Surfaces AI-Discoverable Latent Needs and identifies data-side moats
### Phase 1.5: Assumption Bridge Before moving to solutions, decompose the idea into its critical assumptions: 1. List every assumption that must be true for the theory to hold 2. Rate each by **importance (1-5) × uncertainty (1-5)** 3. Flag the highest-risk assumptions as requiring primary validation This feeds directly into the Validation Confidence block in the output. ### Phase 2: Solution Space (Develop + Deliver)
#QuestionWhat It Forces
**5****What would make them fire their current workaround immediately?**Defines the minimum bar for switching and key differentiators
**5.5****What smaller jobs surround the main job, and could solving a micro-JTBD for two user types create a peer-to-peer surface (templates exchange, peer review, marketplace seed, expert directory, community Q&A) that satisfies an unmet relational need?**Surfaces ecosystem-stitching and network-effect potential; opens the path from product to platform
**6****What is the smallest intervention that captures 80% of the value?**Forces ruthless prioritization, defines MVP
**7****What must be true about the world for this solution to become obsolete in 5 years?**Stress-tests durability, surfaces hidden assumptions
**7.5****Is this Cheap-with-AI (existed, AI collapsed cost), Only-AI-Can-Do (infeasible before modern models), AI-Discoverable Need (need newly visible via AI synthesis), or AI-Optional? Name the asymmetric advantage window and how long it lasts.**Classifies the AI opportunity type and defensibility timing
**8****What is the one metric that, if moved, proves the real problem is solved?**Creates accountability and clarity on success
### Phase 2.5: Pivot Map (MANDATORY before scoring) List the 2–3 most plausible pivots if the riskiest assumption fails. Use Ries' 10-pivot taxonomy: 1. **Zoom-in:** strip down to the single feature that wins 2. **Zoom-out:** broaden into a more holistic offering 3. **Customer-segment:** same product, different buyer 4. **Customer-need:** different problem, same buyer 5. **Platform:** flip from app to platform (or vice versa) 6. **Business-architecture:** flip B2C ↔ B2B, complex-system ↔ volume-operations 7. **Value-capture:** change the revenue model (subscription, outcome, freemium, marketplace fee) 8. **Engine-of-growth:** change the growth loop (paid → viral → sticky) 9. **Channel:** change the path to the buyer 10. **Technology:** swap the underlying tech for a cheaper, faster, or more capable alternative For each plausible pivot, name the **trigger signal** (what evidence would activate it). **Concepts with no plausible pivot are dead-end concepts and must be flagged before scoring.** ### Phase 3: Scoring Score each dimension 0-10 based on evidence quality (not optimism): **Load** Market Evaluation Scoring Kit **for behavioral anchor definitions and evidence tier caps before scoring.**
DimensionWeightWhat You're Scoring
**Problem Severity**20%How acute is the pain? Are there workarounds proving demand?
**Market Size**15%Is the addressable market large enough to build a business?
**Competitive Gap**15%Do existing solutions leave meaningful gaps?
**Differentiation**15%Can this solution win on something that matters to users?
**Feasibility**10%Can this be built/delivered with available resources and technology?
**MVP Clarity**10%Is there a clear, small first version that captures most of the value?
**Durability**8%Will this still matter in 3-5 years?
**Measurability**7%Is there a clear success metric?
**Final Score** = Weighted average × 10 (gives 0-100 scale) **Interpretation:** - **70-100:** Strong idea. Portfolio ready. Worth pursuing next steps. - **50-69:** Promising but needs refinement. Identify specific gaps. - **30-49:** Weak signal. Pivot or park. - **0-29:** No evidence of viable opportunity. Archive with learnings. ### Phase 4: Document in Business Ideas Database **THIS IS THE FINAL STEP OF THE AUTOMATION** **ALWAYS create a page in the** **database. No exceptions.** Every validated idea (regardless of score) gets documented automatically. **Artifact Layout (MANDATORY):** Build and update the page per the . PROMOTE conclusions into the Live Synthesis sections at the top (Verdict, Recommendation & Next Steps, Score Breakdown, Key Risks, Validation Confidence). ARCHIVE the full Phase 0-3 work, Pivot Map, and Pre-Mortem as a new dated Appendix entry at the bottom. LOG one line in the "How this analysis grew" callout. PRESERVE all prior content; Sources stay last. 1. **Create a page** in the database with: - **Idea Name:** Clear, descriptive title - **Status:** "Validated" (score ≥ 50) or "Rejected" (score \< 50) - **Validation Score:** The final weighted score - **Problem Statement:** Synthesized from Phase 1 answers - **Target User:** The specific user segment identified in Q1 - **Tags:** Most appropriate category 2. **Page content** should include: - All Phase 0 (4 theory questions) + Phase 1 (Q1–Q4.5) + Phase 2 (Q5–Q8 including 5.5 and 7.5) questions with synthesized answers - The scoring table with individual dimension scores - **AI Opportunity Classification** badge: Cheap-with-AI / Only-AI-Can-Do / AI-Discoverable Need / AI-Optional - **Pivot Map** from Phase 2.5: 2–3 plausible Ries pivots with trigger signals - **Zero-to-TAM Staircase position:** entry step (0–4) per §11, with the Step 1 → Step 2 climb signal - **Network-Effect Potential rating:** Compounding (P2P core) / Adjacent / None - A "Key Risks" section highlighting the weakest dimensions - A "Next Steps" section with 2-3 concrete actions if score ≥ 50 - Sources used during web research **Phase 5: Persist & Downstream Handoff** 1. **Persona slate offer:** After documenting in the Business Ideas DB, ask: *"Would you like to build the full stress-test persona slate (validated target user + 🏛️ Architectural CTO + 💼 Zero-Tech Investor + 😈 Contrarian Antagonist) and persist it to a Project page?"* If yes, hand off to Infer Persona Slate (Analyst in command) with `context = validate_business_idea`, the Phase 1 target user persona as `anchor_personas`, and the Business Ideas DB page URL as `source_url`. That automation builds the stress-test slate and writes the `🎯 Persona Shortlist` section directly into this Business Ideas DB page so downstream automations read it from the same artifact. 2. **Feature Ideation offer:** Ask the user: *"Would you like to run the Ideation Engine: Business Idea or Feature (💡 Feature Ideator in command) automation to generate feature concepts for this idea's target user?"* If yes, hand off the target user persona, JTBD insights, and validated problem space from Phases 1-2 to the Ideation Engine: Business Idea or Feature (💡 Feature Ideator in command) automation as input context. **The automation is complete once the page is created in the Business Ideas database (and optional Feature Ideation handoff is offered).** ### Chained Automations ⬆️ **Upstream:** - Identify Market Populations to Innovate For (🧭 Market Population Identifier in command) (direct handoff from Phase 8, skipping Market Eval) - Market Evaluation Scoring Kit (handoff with enriched scoring data) - Can also be triggered standalone with any raw business idea ⬇️ **Downstream:** - Infer Persona Slate (Analyst in command) (preferred persona-persistence path: builds full stress-test slate and writes the `🎯 Persona Shortlist` section directly into the Business Ideas DB page itself) - Ideation Engine: Business Idea or Feature (💡 Feature Ideator in command) (generate feature concepts for the validated idea's target user) 🔄 **Handoff type:** `gated` (pauses for user confirmation after Phase 4 documentation) --- **Handoff Contracts:** **⬆️ From Identify Market Populations (direct)** - **Trigger:** User confirms Validate Business handoff at Identify Market Phase 8 - **Payload received:** Selected population data (proto-persona, unmet need signal, attractiveness scores) - **Validation gate:** At least one population selected with proto-persona **⬆️ From Market Evaluation Scoring Kit** - **Trigger:** User confirms Validate Business handoff after Market Eval scoring - **Payload received:** Scored population data (evidence classifications, dimension scores, pre-mortem findings, validation confidence block) - **Validation gate:** Scoring complete with all dimensions rated **→ Feature Ideation** - **Trigger:** User confirms Feature Ideation handoff after Phase 4 documentation - **Payload:** Target user persona (Who/What/Why/Where), JTBD insights (functional/emotional/social jobs), validated problem space from Phases 1-2, Business Ideas DB page URL - **Validation gate:** Page created in Business Ideas DB; target user persona has all four dimensions; user confirmation received --- ## Output Format Present results to the user in chat as a summary before creating the page: - One-line verdict (strong / promising / weak / no-go) - Top 3 strengths - Top 3 risks - The final score - **Validation Confidence block** (evidence basis, strongest tier used, assumptions needing primary validation) - **Pre-mortem** (most likely failure mode, hidden dependency, competitive response). Use the templates from Market Evaluation Scoring Kit. - **AI Opportunity Classification** (Cheap-with-AI / Only-AI-Can-Do / AI-Discoverable Need / AI-Optional) - **Top 2 Pivot Options** with trigger signals (from Phase 2.5) - **Zero-to-TAM Staircase entry step** (0–4) and Step 1 → Step 2 climb signal - **Network-Effect Potential** (Compounding / Adjacent / None) - **Automatically save to the Business Ideas database. Do not ask for confirmation.** Every validated idea gets an entry, regardless of score. --- ## Rules - **ALWAYS create an entry in the Business Ideas database**, even for rejected ideas. Every evaluation gets documented. No exceptions. - **NEVER delete validated ideas** from the database - **Always use web search** to ground answers in real market data - **Be honest.** The value of this system is brutal honesty, not validation of the user's enthusiasm - **Score based on evidence**, not potential. "This could be big" scores low. "Here's data showing X" scores high. - Ideas scoring ≥ 70 are automatically flagged as Portfolio Ready via the formula property - **ALWAYS classify the AI opportunity type** (Cheap-with-AI / Only-AI-Can-Do / AI-Discoverable Need / AI-Optional). Ideas tagged AI-Optional must justify differentiation independent of AI. - **ALWAYS produce a Pivot Map** in Phase 2.5 with at least 2 plausible pivots and trigger signals before scoring. Concepts with zero plausible pivots are flagged as dead-end. - **ALWAYS apply the AI Discovery Gap question** in Phase 1 (Q4.5). Hidden latent needs surfaced by previously inaccessible data are the highest-value 2026 opportunity class. - **ALWAYS name a Zero-to-TAM Staircase entry step** (0–4) so the user sees the \$0 → max-TAM conditional climb path. - **ALWAYS rate Network-Effect Potential** (Compounding / Adjacent / None). Concepts that connect end-users to each other graduate the Staircase faster. --- **Framework Source:** Adapted from (Double Diamond + JTBD + Theory-Based View synthesis) **Scoring Reference:** Market Evaluation Scoring Kit (anchors, evidence taxonomy, pre-mortem, validation confidence)
