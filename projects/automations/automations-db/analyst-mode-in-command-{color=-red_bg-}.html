Process & Distribute Research Report [Analyst in Command]

Mar 06, 20265 min read

Analyst Mode in Command {color=“red_bg”}

### INPUT 1. **Link to Notion page** containing the pasted report content (or report text pasted directly in chat) 2. **Research intent** (1-2 sentences): what question was the user trying to answer? 3. **Source type** (optional): Perplexity, ChatGPT, Claude, Web Article, PDF, Systematic Literature Review, Other (defaults to Perplexity if unspecified) --- **🔗 Auto-Handoff from SLR Automation** When chained from Systematic Literature Review (Analyst Mode), all three inputs are pre-mapped per the Chained Automations contract below. Do NOT re-prompt the user. Accept the mapped values and proceed directly to Phase 1. ### STEPS: **Phase 1: ARCHIVE** 1. Create a new entry in with the report title, source type, topics, research intent, and today's date. Set Status to "Processing." 2. If the report was pasted in chat (not already on a Notion page), paste the full original text into the body of the Source Reports DB entry to preserve the raw report. 3. If the report was already on a Notion page, note that page link in the entry body as the original source. **Phase 2: CLASSIFY** 1. Read the full report content. Identify: - Primary domain(s) and topic(s) - Key findings, frameworks, insights, tools, people, and action items - The user's research intent (what they were trying to learn) **Phase 3: ROUTE (against Database Index)** 1. **Map each information chunk to the most specific destination.** Route to the deepest matching page, not the top-level hub. 1. **Integration-first rule (MANDATORY):** Always prefer synthesizing content into an existing page over creating a new one. Before routing, scan the target destination's sub-pages for a topical match. If a sub-page covers ≥60% of the same topic, integrate there. New pages only when no existing page is a reasonable fit. 2. **New page confirmation gate:** If no existing page fits and a new page is warranted, **STOP and confirm with the user** before creating it. Present: (a) the proposed title, (b) the parent location, (c) a one-line rationale for why no existing page fits. Only proceed after user approval. **Phase 4: INTEGRATE** 1. For each destination, integrate the relevant content following the destination's formatting rules and existing structure. 2. When synthesizing into existing pages, match the page's current format and style. 3. Add citations or source references back to the archived report in the Source Reports DB. **Phase 5: LINK & CLOSE** 1. Update the Source Reports DB entry's "Integrated To" field with links to every page that received content. 2. Set the Source Reports DB entry Status to "Processed." 3. Confirm to the user: summary of what was found, where it was routed, and a link to the archived report. ### CHAINED AUTOMATIONS - ⬆️ **Upstream:** Systematic Literature Review (Analyst Mode) - ⬇️ **Downstream:** None (terminal output) - 🔄 **Handoff type:** `auto` (upstream proceeds without pause after SLR S6 or quick bypass completes) **Handoff contract (receiving from SLR):** - **Trigger:** SLR S6 report finalization completes (FSM path) OR SLR quick bypass step 7 completes - **Payload received:** - Link to Notion page → the Research Project page URL from SLR S5/S6 - Research intent → the original research question from SLR S0 - Source type → `Systematic Literature Review` (hardcoded) - **Validation gate:** Research Project page must exist with Status = `Synthesis` or `Writing`, and at least one Literature Library entry must be linked. If either condition fails, halt and notify the user before proceeding. - **Context continuity:** The Research Project page already contains the full synthesis, search strategy, gap analysis, and recommended reading. Treat it as the report content for classification and routing. Do NOT re-prompt the user for inputs that are already mapped. ### Rules - **NEVER discard the original report.** The full text must be preserved in the Source Reports DB entry. - **Synthesize, don't dump.** Integrate findings into existing pages where they strengthen what's already there. - **Route against the Database Index every time.** Don't assume destinations from memory. - **Maintain traceability.** Every destination page should reference the source report. Every source report should list its destinations. - Take a step back and review your final work before you finish. ### Output 1. Archived report in Source Reports DB (Status: Processed) 2. Content integrated across relevant Notion pages/databases 3. Brief summary to user: what was found, where it went, link to archive entry 4. Prioritize brevity over flattery.
