Sync Block Reference

Nov 15, 20265 min read

**Complete reference for sync block patterns and best practices.** Sync blocks are the nervous system of multi-agent architectures. For actionable instructions, see the main Meta-Agent Master Prompt. --- ## ⭐ Why Sync Blocks Matter Sync blocks provide: - **Real-time propagation** — Changes appear instantly across all embedded locations - **Single source of truth** — No stale copies, no sync conflicts - **Bidirectional editing** — Any agent can update from any location - **Version coherence** — All agents always see the same state - **Zero-cost communication** — No message passing overhead --- ## 🎯 Sync Block Topology Patterns ### Pattern 1: Hub & Spoke (Broadcast) **Use when:** One source, many consumers ```javascript ┌─── Agent A (embed) │ [HUB] ─┼─── Agent B (embed) │ └─── Agent C (embed) ``` **Implementation:** 1. Create sync block in System Overview page 2. Embed `` in each agent page 3. Only coordinator writes; others read **Best for:** Global context, constraints, user requirements ### Pattern 2: Daisy Chain (Pipeline) **Use when:** Sequential handoffs between agents ```javascript Agent A ──[sync A]──▶ Agent B ──[sync B]──▶ Agent C (write) (read/write) (read/write) ``` **Implementation:** 1. Each agent owns ONE output sync block 2. Next agent embeds previous agent's sync block 3. Chain forms: A→B→C→D **Best for:** Content pipelines, research chains, approval workflows ### Pattern 3: Mesh (Multi-Reader/Writer) **Use when:** Multiple agents collaborate on shared artifact **Implementation:** 1. Single sync block with structured sections 2. Each agent writes to designated section 3. All agents can read entire block **Best for:** Collaborative documents, shared findings, consensus building ### Pattern 4: Layered (Hierarchical) **Use when:** Parent-child agent relationships **Implementation:** 1. Global sync embedded everywhere 2. Team syncs embedded only in team members 3. Workers inherit both global + team context **Best for:** Large systems, department isolation, need-to-know context --- ## 📝 Sync Block Content Templates ### Global Context Sync Block **Purpose:** System-wide shared state visible to ALL agents ```markdown ## 🌐 GLOBAL CONTEXT --- ### Workflow Metadata - **Workflow ID:** WF-2026-001 - **Started:** 2026-01-17T20:30:00 - **Current State:** S2: Research - **Active Agent:** 🔍 Researcher

⚙️ Sync Block Operations Protocol

### READ Operation **When:** Agent needs context before acting 1. View the agent page (sync blocks auto-load) 2. Parse relevant sections from embedded sync blocks 3. Extract into Input Buffer or Working Memory 4. Never modify during read-only operations ### WRITE Operation **When:** Agent produces output or updates state 1. Identify target sync block (own output sync or global) 2. Update ONLY designated sections 3. Include timestamp and agent identifier 4. Propagation is automatic to all embedded locations ### CREATE Operation **When:** New agent needs its own output sync block 1. Create `` in agent's page (no URL = new block) 2. After creation, URL is assigned automatically 3. Wire by embedding `` in listener pages 4. Register sync block URL in Agent Registry for tracking --- ## 🚨 Sync Block Anti-Patterns ### ✘ DON'T: Duplicate Sync Content **Problem:** Copying sync block content instead of embedding **Result:** Content gets stale → DIVERGENCE **Fix:** Always use `` for shared content ### ✘ DON'T: Create Circular Syncs **Problem:** Agent A embeds B, B embeds A **Result:** Infinite recursion risk **Fix:** Use Hub & Spoke for shared context; daisy chain for outputs ### ✘ DON'T: Overload Single Sync **Problem:** One giant sync block with everything **Result:** Too much context, slow updates **Fix:** Separate by purpose (Global, per-Agent Output, Collaboration) ### ✘ DON'T: Write Without Sections **Problem:** Multiple agents clobber each other's content **Result:** Race condition, content lost **Fix:** Designated sections per agent --- ## 🎯 Advanced Sync Strategies ### Strategy 1: Versioned Sync Blocks **Purpose:** Track changes over time within sync blocks **Use when:** Audit trails needed, debugging iteration loops ### Strategy 2: Signal Flags in Sync **Purpose:** Lightweight agent-to-agent signaling without state transitions Example flags: `READY_FOR_REVIEW`, `NEEDS_INPUT`, `BLOCKED`, `COORDINATOR_ATTENTION` ### Strategy 3: Structured Data Exchange **Purpose:** Pass queryable data (JSON) between agents **Use when:** Downstream agents need to parse/filter data programmatically ### Strategy 4: Cross-Workflow Sync Inheritance **Purpose:** Reuse context from previous workflows **Use when:** Building institutional knowledge, learning from past executions --- ## 📐 Sync Block Wiring Checklist ### Before Executing Any Multi-Agent System: - [ ] **Global Context sync block** created in System Overview - [ ] Global Context **embedded in every agent page** - [ ] Each agent has **own output sync block** (if producing outputs) - [ ] Output sync blocks **embedded in correct listener pages** - [ ] No circular embedding patterns - [ ] Each sync block has **designated write sections** for each contributor - [ ] Sync block URLs **registered in Agent Registry** (if tracking) - [ ] **Test propagation:** update source, verify all embeddings reflect change
